# Proposal: envelope v2 — identity, threads, terminal authority, capability

Status: **draft 3 — contracts pinned, awaiting GO**
Targets: v0.8.0 (envelope v2 + identity + manifest), v0.9.0 (cross-project)
Draft 1 proposed universal receipts → **deferred** (§11). Draft 2 left four contracts
under-specified → pinned here as §3–§7.
Prior art: [agent-message-queue](https://github.com/avivsinai/agent-message-queue),
[agent-bus](https://github.com/MustaphaSteph/agent-bus),
[A2A](https://a2a-protocol.org/) (Linux Foundation, v1.0 2026).

## 1. What each draft got wrong, and why it is recorded

Kept so nobody re-derives these the hard way:

| Draft | Rejected premise | Why it was wrong |
|---|---|---|
| 1 | outcomes must live in a receipt | the reply is already an immutable, no-replace, exact-id artifact — and it carries the result too |
| 1 | receipt per `<msg>.<participant>` | write-once storage cannot hold a `blocked → done` transition |
| 1 | `status: open\|fyi` | verified: the drain at `SKILL.md:144` matches `status: open`, so `fyi` is **invisible** to a v0.7 reader |
| 1 | `<kind>-<tab>` as participant id | a locator, not an address: pane move / rename / restart strands an already-published message |
| 1 | PROTOCOL version stamp as handshake | `bootstrap.sh` deliberately never rewrites it, and a human can type anything there |
| 2 | earlier ULID wins a cancel race | ULIDs are only approximately ordered, and a cancel can be published *after* irreversible work is done |
| 2 | quoting `subject` fixes YAML | agent text also contains quotes, backslashes, newlines |
| 2 | `envelope_schema: 2` licenses dropping legacy | a file on disk says nothing about what a **live, already-running** reader understands |

## 2. Scope

**v0.8.0** — envelope v2, participant identity + binding, capability manifest, canonical
frontmatter. One envelope migration; no new artifact lifecycle; no waiter.

**v0.9.0** — cross-project routing, gated on the manifest.

**Deferred** — receipts, blocking waiter (§11).

## 3. Contract A — identity and binding lifecycle

The core split: **a logical participant is durable and immutable; the live process holding
it is a separate, mutable binding.** Transport coordinates (pane, tab, herdr name, session)
appear only in the binding, never in identity and never in a published message.

```
collab/participants/<id>.json     # immutable identity, one file per participant
collab/bindings/<id>.json         # mutable: which live process currently holds <id>
```

```json
// participants/codex-reviewer.json — created once, no-replace, never rewritten
{ "id": "codex-reviewer", "kind": "codex", "alias": "Codex", "created": "2026-08-26T…Z" }

// bindings/codex-reviewer.json — replaced whenever the process or its coordinates change
{ "participant": "codex-reviewer",
  "herdr": { "pane_id": "w3:pD", "tab_id": "w3:t6", "agent_session": "01a033e7-…" },
  "reader_schema": 2,
  "bound_at": "2026-08-26T…Z" }
```

**Lifecycle, each step with a deterministic rule:**

1. **create** — `register-participant <id> --kind <k> [--alias …]` writes the identity
   artifact with a no-replace link. A concurrent duplicate **fails atomically**; there is
   no shared file to lose an update on (§4).
2. **claim** — `bind-participant <id>`, run **by the agent itself from its own pane**. It
   resolves its own live coordinates (`herdr pane current`, plus its session id) and writes
   the binding. *This is how a process answers "which one am I?" — it is told, and it
   claims. Identity is never inferred from the filesystem.*
3. **pane move / rename** — logical id unchanged; the binding's coordinates go stale. Any
   agent re-runs `bind-participant <its own id>` (cheap, idempotent) at turn start, or when
   resolution fails.
4. **restart** — a new session id, so the old binding no longer matches any live agent. The
   agent re-binds **with its explicit id**, which it knows because the id is part of its
   briefing (PROTOCOL + the onboarding message name it). Not discoverable, by design.
5. **duplicate live claim** — if a binding exists whose `agent_session` still appears in
   `herdr agent list` as a *different* running agent, `bind-participant` **refuses**;
   `--takeover` is required and is recorded in the new binding. Stale bindings (session
   absent) are re-bound without ceremony.

**Executable oracle for the restart test** (draft 2 had none): publish a message to
`to_agent: codex-reviewer`; restart that agent; run `bind-participant codex-reviewer`;
assert the binding's `agent_session` changed, `participants/codex-reviewer.json` is
byte-identical, and the pre-restart message is still claimable by the new process.

## 4. Contract B — registration is explicit, never a send-time side effect

- A sender **never** mints an identity for a recipient. Registration is its own step,
  before the first send.
- **One artifact per participant** (`participants/<id>.json`), published no-replace — so two
  initiators racing to register the same id cannot lose an update, and racing on *different*
  ids cannot conflict at all. (A single shared `participants.json` would need lock/CAS; this
  sidesteps it.)
- `bootstrap.sh` may **pre-declare logical endpoints** — `claude-primary` and
  `<peer>-primary` — because logical identity does not need a live agent. It creates only
  what is **missing** and never rewrites an existing participant artifact (ownership rule:
  `bus.json` is bootstrap-owned; participants are multi-party data).
- A peer-initiated bootstrap therefore still yields a usable bus; as with herdr wiring,
  scaffolding does not imply a bound endpoint, and `bootstrap.sh` stdout must say so and
  name the next step.
- Adding a third participant later = `register-participant` + `bind-participant`, done by a
  human or an orchestrator. No implicit growth.

## 5. Contract C — terminal authority belongs to the recipient

**Cancel is a request, not a verdict.**

- The sender publishes `type: cancel-request` in the same thread, naming the original in
  `cancels: <request-id>`.
- The **recipient of the original request is the sole authority** for that request's
  terminal outcome.
  - Not yet committed → it replies to the **original** with `outcome: canceled`, and may ack
    the cancel-request.
  - Already terminal, or past the point of no return → it replies to the **cancel-request**
    with `outcome: rejected` (note: too late). The original keeps whatever terminal outcome
    it earned.
- ULID order is **not** used to decide anything. It is approximately time-ordered only
  (same-millisecond random tails; cross-machine clock skew), and ordering does not reflect
  whether irreversible work happened.

**Terminal-result uniqueness query** — used by crash recovery and by "is this handled?":

> a request `R` is handled **iff** there exists a message with `reply_to == R.id` **and**
> `from_agent == R.to_agent` **and** a terminal `outcome` (`done|rejected|failed|canceled`).

Questions and updates in the same thread carry **no** `outcome` and therefore can never be
mistaken for completion — the failure mode draft 1's `blocked` receipt would have created.

## 6. Contract D — capability describes live readers, not files on disk

`collab/bus.json`, bootstrap-owned and atomically replaced:

```json
{ "project_id": "01M0…",        // minted once, opaque; NOT derived from a directory name
  "project_alias": "takumi",     // display only, may change freely
  "schemas": { "read": [1, 2], "write": 2, "min_reader": 1 },
  "publisher_version": "0.8.0" }
```

- `read` — what this endpoint's tooling can parse; `write` — what it emits; `min_reader` —
  the floor it *demands of others*. Raising `min_reader` is the only thing that licenses
  dropping legacy fields.
- **A live participant's reader schema lives in its binding**, not in `bus.json` — because
  it is a claim about a running process, and updating a file on disk does not hot-reload an
  agent session that started yesterday.
- **Dropping `pair` / `status: open` requires all three:** the target's *current binding*
  declares `reader_schema ≥ 2`; no active binding declares `< 2`; and `min_reader` has been
  explicitly raised by a human-initiated migration step. Until then, emit legacy — two cheap
  fields. **Recommended default: keep them through v0.8 and v0.9.**

## 7. Contract E — canonical frontmatter, enforced at publish

Not writer discipline — a **gate**. `publish.sh` refuses a draft whose frontmatter is not
canonical, so malformed YAML can never enter the bus (rather than being discovered later by
a reader).

- **Machine tokens** (`schema`, `id`, `thread`, `reply_to`, `from`, `to`, `from_agent`,
  `to_agent`, `intent`, `type`, `outcome`, `status`, `pair`) — allowlist patterns, unquoted.
- **Human strings** (`subject`, `alias`, `note`) — **single-quoted YAML**, interior `'`
  doubled, **newlines forbidden**. Single-quoted style has no backslash processing at all,
  which removes the escaping hell that double quotes invite.
- **Writers**: `collab/bin/fm-quote.sh <string>` for scripts; agents follow the same rule,
  and the publish gate catches them when they do not.
- **Validator**: `collab/bin/check-envelope.sh` does a conservative, dependency-free lint
  (delimiters, allowlisted keys, quoting rules, no tabs). If a real YAML parser is available
  (`ruby -ryaml`, or python with a yaml module) it *additionally* does a safe-load — an
  optional strengthening, never a hard dependency.
- **Readers**: safe-load; on a bad file, fail **loudly for that file and continue** scanning
  the rest of the inbox.

Live evidence this is needed: of 119 archived messages, one has a `subject` containing
`": "`, and a real parser rejects it — *the draft-1 review request itself*.

## 8. The envelope (schema 2)

```yaml
---
schema: 2
id: 01M0…                    # ULID, also the filename prefix
thread: 01M0…                # conversation id; first message uses its own id
reply_to: 01M0…              # OPTIONAL — absent on the first message of a thread
cancels: 01M0…               # only on type: cancel-request
from: claude                 # kind (also the inbox/to/ directory)
to: codex                    # kind
from_agent: claude-primary   # stable participant id
to_agent: codex-primary      # stable participant id — routing keys off this
intent: action               # action | fyi  (what the sender wants; not lifecycle)
type: review-request
subject: 'single-quoted; interior '' doubled; no newlines'
outcome: done                # ONLY on a recipient-authored terminal reply:
                             # done | rejected | failed | canceled
status: open                 # LEGACY, still written (v0.7 readers drain on this)
pair: w3:t6                  # LEGACY, still written
---
```

Routing rule: **process messages whose `to_agent` is my participant id.** Exact, and it
works with three agents in one tab — the actual mesh blocker.

## 9. Backward compatibility

- **Readers accept both.** No `to_agent` → fall back to `pair == my tab_id`. No `thread` →
  the message's own `id`. No `schema` → schema 1.
- **Writers emit both.** v0.8 writes the new fields *and* `pair` + `status: open`.
- Legacy fields drop only under §6's three conditions — expected to stay through v0.9.
- `bootstrap.sh` migrate creates `bus.json`, `participants/`, `bindings/` when **missing**,
  never rewriting existing ones, and still never touches PROTOCOL.md.

## 10. v0.9.0 — cross-project

`collab/peers.json`: `{ "peers": { "spec-agents": "/abs/path/to/their/collab" } }`

- `next-id.sh --to-project <name>` allocates the draft in the peer's root; publish links it
  into their inbox. Messages stamp `from_project` / `reply_project` (the **opaque
  `project_id`**, not the alias) so replies route home across renames.
- Safety: the foreign root gets the same treatment bootstrap applies to its own — refuse a
  symlinked root/inbox, refuse non-regular destinations, never write through an inode.
- **Refuse on skew, never silently downgrade**, decided from the foreign `bus.json`
  (`schemas.read` / `min_reader`), never from PROTOCOL.md prose. A later explicit
  `--compat-envelope 1` may be offered, listing what would be lost, requiring opt-in.

## 11. Deferred: receipts and waiter

No instance yet justifies them: for ordinary requests the reply *is* an exact-id durable
receipt (§5's query); for `fyi`, the archive move is the handled marker; and the one failure
that actually hurt — a silent content-filter refusal — is exactly what a recipient-authored
receipt cannot record either.

If ever added: (1) a `done` receipt is published only after the result and all durable side
effects; (2) it points at its `result_message`; (3) `blocked` never occupies a terminal slot;
(4) cancel/complete precedence follows §5; (5) layout is
`receipts/<message-id>/<participant-id>.md`, never split on `.`. A waiter stays out of
`knock.sh` — it would be a separate `wait-result.sh <request-id>` with a bounded, monotonic
deadline. With mutual `--submit-only` proven end to end, blocking is the exception.

## 12. Test plan (oracles, not vibes)

- **envelope**: a v0.7 message (`pair`, `status: open`, no `schema`) and a v0.8 message drain
  side by side; a v0.8 message is seen **and archived** by a v0.7 reader.
- **routing**: three participants in one tab; each processes only its own `to_agent`.
- **identity**: pane move, herdr rename, and full restart → §3's oracle (binding session
  changes, identity artifact byte-identical, pre-existing message still claimable).
- **duplicate claim**: a second live process claiming a bound id is refused; `--takeover`
  succeeds and is recorded; a stale binding re-binds without `--takeover`.
- **registration**: two concurrent `register-participant <same id>` → exactly one wins, no
  lost update; `bootstrap.sh` on a bus with an existing registry changes nothing in it.
- **cancel**: cancel arrives before commit → `outcome: canceled` on the original; cancel
  arrives after a terminal result → cancel-request `rejected`, original outcome unchanged.
  Both orders deterministic, neither decided by ULID.
- **recovery**: a question/update in the thread does **not** satisfy the handled query; a
  terminal reply from the right author does.
- **frontmatter**: `subject` containing `": "`, `'`, `"`, `#`, and a newline attempt — the
  publish gate rejects the bad ones and round-trips the good; a corrupt file in the inbox
  fails loudly *for that file* while the rest of the drain proceeds.
- **capability**: a hand-edited PROTOCOL stamp changes no decision; legacy fields are still
  emitted while any active binding declares `reader_schema < 2`.
- **cross-project (v0.9)**: symlinked foreign root refused; lower foreign `schemas.read`
  refused with a clear message; reply routes home by `project_id` after an alias rename.

## 13. Remaining open questions

- **Q1** — should `bind-participant` run automatically at turn start (cheap, keeps
  coordinates fresh) or only on demand/when resolution fails? Automatic is more robust but
  writes a file every round.
- **Q2** — `register-participant` / `bind-participant`: separate scripts, or subcommands of
  one `participant.sh`? (They share validation and the atomic-write helper.)
- **Q3** — does the identity artifact need `created`, given ULIDs are not used for ids here?
  Ids are human-chosen (`codex-primary`), which is what makes them briefable.

## 14. Implementation gate — **GO** (draft 3 approved)

Approved for implementation. Three conditions were added at approval and are binding:

1. **Binding claims must be serializable, not merely atomic.** Atomic replace of
   `bindings/<id>.json` stops a half-write; it does **not** stop two processes claiming the
   same absent/stale binding from both succeeding. The bind path serializes per participant,
   and a genuinely concurrent test must show **exactly one** winner with the other refused;
   `--takeover` stays explicit. The guarantee is scoped to **one host/runtime** — a synced
   folder is not a cross-machine lease and must not be described as one.
2. **The publish gate is version-aware, and `refs` is part of the contract.** Measured
   against the live bus: `refs` appears in **117 of 126** messages, so omitting it from the
   allowlist would lock the running bus out of its own gate. Schema 1 accepts the existing
   field set (`id, from, to, type, subject, refs, status, pair, reply_to`; `status` in
   practice takes `open|done|closed`); schema 2 uses the strict set with `refs` retained as
   an optional single-quoted human scalar.
3. **A duplicate terminal outcome is a protocol conflict, not a tie-break.** The handled
   query (§5) must return 0 or 1. If **two** terminal outcomes exist from the correct
   recipient for one request, the reader reports a conflict and refuses to pick — which is
   what keeps "no ULID ordering" honest.

Answers folded in: `participant.sh` is one script with `register|bind|ensure|show`
subcommands (`--takeover` only on `bind`); turn start runs `ensure`, which re-resolves and
**no-ops when nothing changed**, never auto-taking-over a live holder; `created` stays as
audit metadata (RFC 3339 UTC) with an explicit rule that it is never used for ordering,
identity, staleness, or takeover.

### 14.1 Measured state of the live bus

Scanned 126 messages (archive + open) before writing any code:

- keys in use: `id` 125, `from` 125, `to` 125, `type` 125, `subject` 125, `status` 125,
  **`refs` 117**, `pair` 93, `reply_to` 28 — nine keys, no others.
- `status` values in the wild: `open`, `done`, **`closed`** (the last from FYI-style
  messages) — the schema-1 validator must accept all three.
- `type` values: `ack, question, reply, review-request, review-result, task`.
- **13 messages carry an unparseable plain scalar** — mostly `refs:` values containing
  `": "`. Draft 2 reported one because it only checked `subject`. These are already
  published and stay as they are; the gate governs new publishes only.

### 14.2 Build order (approved)

1. **Foundation** — v1/v2 fixtures and round-trip/negative tests **first**, then the shared
   parser, canonical serializer, `fm-quote.sh`, version-aware `check-envelope.sh`, and only
   then wire the gate into `publish.sh`. Templates and writer guidance must be updated in
   the same change, or the strict gate locks the live bus out of itself.
   **The first test is v0.7 and v0.8 messages passing side by side — not the new format alone.**
2. `bus.json` atomic writer + bootstrap migrate: a re-run preserves the opaque `project_id`;
   a malformed or id/kind-mismatched existing participant fails loud rather than counting
   "exists" as success.
3. `participant.sh` register/bind/ensure + concurrent-claim, pane-move, rename, restart oracles.
4. Schema-2 exact routing, schema-1 fallback, live-reader capability decisions — `pair` and
   `status: open` still emitted.
5. Outcome/cancel/recovery + duplicate-terminal conflict detection, then a three-participant
   dogfood.
